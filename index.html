a living code repository

The file stops being the unit.

Every function, type, and constant is an object in a graph. History stores the change, not the snapshot. A branch is a notebook that exists only for the task.

01 — what does not work

Three habits an AI inherits and should not.

  1. The whole file. To change one function, the context loads the rest of the file. In Meristem the object is the addressable piece.
  2. The snapshot. Git stores the state. The event log stores what changed, when, and from which base. Any point can be read again.
  3. The branch that stays. Here the branch is a change-set. Dropping the task leaves nothing behind. Only promotion enters the head.

02 — how a change lives

Four steps, and only the last one persists.

A function, a type, a constant. Its own address in the graph, readable without opening the neighbor.

id: site/index.html
kind: snippet
language: html

03 — the first interface

The command comes up. The repository does the rest.

The CLI is the client. It starts the seed images and asks the deploy flow to bring up runners, the gateway, and whatever else lives in the graph. Finer management, on the web, comes next. The page you are reading is an object too.

$ meristem up
repository   8080  healthy
builder      8096  healthy
gateway      8095  healthy
$ meristem stats

04 — vocabulary

Few words, used the same way every time.

object
The smallest unit of code. Not a file.
flow
A view assembled on demand over the graph.
change-set
The notebook for a task. Disposable.
head
What the runners execute right now.
